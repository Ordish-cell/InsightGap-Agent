# 会话文件跨轮读取

## 使用与回退

后端重启后生效。发送附带文件的消息后，同一会话可以继续追问文件，不需要重新上传；仅上传而未发送的文件不加入会话清单。

`CHAT_DOCUMENT_PATH_ENABLED=true` 默认开启纯文本文档短路径。设为 `false` 后，文档读取回退已有工作流，已校验的文件 ID 保留。`CHAT_FAST_PATH_ENABLED` 继续控制普通聊天入口；文档开关开启且会话有文件时仍允许文档入口判断。两个开关都关闭时执行旧入口。

不需要新增表、数据库迁移、历史回填或重新切片。旧错误回答不会自动改写。

## 实现

- 文件清单来自当前用户、当前会话的用户消息附件快照，分页读取元数据，并查询 Document 的实时状态。最近消息截断不影响附件关联。不存在/不可访问文件保留不可用标记。
- 入口模型获得清单、最近消息、摘要和最近已完成回复的文件记录。首行支持受校验 JSON 的 chat/document/clarify/workflow 及旧 chat/workflow；完整 JSON 在 EOF 时同样校验。最多缓存 512 字符。
- document 指定最多 3 个清单内 ID、overview/search 和明确化问题。校验失败只回退一次为文件澄清，不尝试越界或无范围读取。澄清候选保存在助手消息 metadata.file_context；模型负责自然语言指代判断，仍存在模型选择错误的可能。
- 短文件按顺序直接读取文本。长文件概览使用已有摘要/目录，否则标记部分内容；具体问题检索强制限制文档 ID。默认读取上限 8,000，另受现有 GSSC 输入预算限制，按 UTF-8 字节保守计量，最多三份文件分配剩余预算。当前默认 GSSC 预算 4,000，所以实际允许正文会小于 8,000。
- 只读工作线程使用独立数据库会话，读取等待上限 30 秒。取消不等待底层同步调用真正退出，迟到结果不会写入账本或答案。单进程执行边界保持不变。
- conversation detail 增加 files；run 状态保存 conversation_files/file_context，助手消息保存文件决策、范围、引用和澄清候选。正文不写入文件清单。
- 纯文档不再在图前预检索，回答复用当前会话模型、answer_delta、完成持久化及后台摘要。混合图片附件仍走原路径。研究/工具/审批仍由原 LangGraph 节点管理及关闭聊天控制。
- 文档节点使用真实开始/完成/失败/取消事件；进展区只显示实际读取文件及覆盖范围。刷新使用既有账本恢复，不重读文件。

## 限制

只处理已有解析器产出的文本。没有新增 OCR、图片跨轮理解或通用工具循环。自然语言文件指代依赖当前模型，无法保证所有模糊表达都判断正确；有歧义时通过澄清减少误选。旧流程自身的同步阻塞及已有失败未重构。没有自动重放重启前任务，没有提交、推送、部署或修改现有会话数据。
