# 记忆机制：作用域、整理与连续性

本次改造位于 `codex/memory-mechanism`，沿用 PostgreSQL、Qdrant、Neo4j 和既有对话摘要/历史段存储。

## 默认行为与控制

- `use_memory=true`：允许启动时注入稳定个人偏好、按问题搜索长期记忆和图召回。
- `generate_memory=false`：自动长期记忆整理默认关闭。开启后仅处理当时允许生成记忆、成功完成的新轮次；不重新提取旧对话。
- 明确要求保存仍立即执行，保留真实保存回执。称呼、回答语言和简繁偏好在未开启自动整理时继续走基础事实确认流程。
- 开启自动整理后，明确的基础个人事实可直接保存；其他事实由后台整理，不向已经结束的回复追加“已保存”。
- 本轮明确设置 > 会话设置 > Profile 默认值。`write_memory=false` 或本轮明确“不要记住/不要保存”阻止本轮写入。
- 关闭使用不会隐藏管理记录，也不会清除当前会话历史和用于连续性的会话摘要。
- 界面开关统一放在长期记忆页；聊天输入区不展示会话记忆控件。开启一次后由后台自动整理后续已完成轮次。

Profile GET/PUT `/api/v1/profile/me` 增量支持两个布尔字段。会话 GET/PATCH
`/api/v1/agent/conversations/{id}/memory-settings` 支持同名字段；PATCH 传 `null` 可恢复继承。
运行请求的 `use_memory`、`generate_memory` 为可选布尔值。运行保存当时的有效策略、覆盖值与设置版本。

## 作用域与有效事实

| scope | 用途 | scope_id |
|---|---|---|
| `user` | 称呼、语言、简繁、回答风格，以及有原文依据的明确长期个人偏好 | 空字符串 |
| `conversation` | 项目背景、目标、技术方案、约束、进度 | 原会话 ID |
| `legacy_unscoped` | 无法可靠确认来源的旧背景，只供管理 | 空字符串 |

写入会校验用户与会话归属，运行来源由服务端解析。模型提供的 scope 或 `source_verified`
不能替代归属和原文校验；技术事实即使被模型错误标成个人分类也不能因此扩大共享范围。

聊天统一排除非 active、隐藏、过期、敏感、低置信和不属于当前作用域的记录。
向量和图结果必须重新查 PostgreSQL；图的旧文本、分类和关系提示不作为事实使用。
派生摘要的全部来源记忆也必须仍然有效。

查询合并向量候选与数据库关键词候选。无效向量命中不会阻止数据库回退，无关键词匹配时返回空。
稳定个人偏好单独注入；不再使用无关的近期高重要性背景补满查询结果。
管理页可按状态、类别和作用域筛选，全部状态包括隐藏历史；候选可以由用户确认。
旧 Memory API 的管理搜索保留用户自己的工作记忆和历史记录，管理查询与聊天召回使用不同权限规则。

## 更新、证据和索引

- 相似度只筛选候选；结构化语义比较区分重复、补充、纠正、无关与模糊冲突。比较失败保持 pending。
- 重复合并来源证据，按不同来源消息 ID 计数；重试不会重复累计，也不会反复提高重要性。
- 补充与纠正生成新版本，事务内同时 supersede 旧版本。称呼等固定字段保留原子替换入口。
- 旧来源的重复证据可以合并，但不会回退最新来源；较旧轮次的纠正不能覆盖新事实。
- 用户编辑明确指定某条事实，生成同作用域的新版本并保留旧文本与版本关系。
- 新记录携带 fact_key、原文引用、来源消息、来源运行、证据数组和版本关系。没有可验证原文的提取候选不激活。
- PostgreSQL 提交后才写向量和图索引。事实保存成功与索引成功分别返回。
- 索引失败保存 `index_pending`。启动恢复及每 30 秒的后台扫描重试；向量点使用稳定 ID，重复写入不产生新副本。
- 成长服务使用相同更新入口；反思与整理按作用域生成派生摘要，不删除原证据，也不再只提升记忆类型。
- `scripts/backfill_memory_vectors.py` 在回填前重新验证 PostgreSQL 记录，执行相同作用域、状态和删除规则。

## 后台整理与取消

`memory_maintenance_tasks` 保存用户、会话、运行、来源消息（处理范围）、状态、尝试次数、错误和结果。
同一运行只建一条任务。处理成功完成的用户消息，以用户原文作证据；助手建议不能成为个人偏好。
后台提取不使用助手输出。工具结果也不会被自动提升为个人事实。

后台工作槽位最多 2 个，同一会话串行处理；失败最多尝试 3 次，重启恢复未完成任务。
回复已提交但任务未入队时，恢复扫描仅补建有运行级生成许可的新轮次，不处理无许可的旧历史。
提交前再次核对设置版本和会话删除状态。关闭再开启不会复活旧任务的许可。
清空会话会取消未完成整理、归档会话记忆、删除连续性摘要，并推进会话处理代次。
清空前启动的摘要、历史段和运行写入不能恢复旧内容。删除会话清理会话记忆及整理任务，保留个人共享记忆。

并发和删除边界沿用项目现有单进程任务管理方式；生产运行应保持一个应用工作进程。
数据库事务仍使用用户行锁串行化事实版本更新。跨应用进程的持久任务分布式抢占不属于本次新增能力。

## 对话连续性

历史快照、近期消息和历史段生成不再截取固定字符前缀。
使用 tokenizer 计量预算，长消息按 UTF-8 完整字符边界分块，逐块合并摘要。
近期历史、会话摘要、长期记忆有独立预算，超预算时保留头尾，避免整包丢弃。
摘要提示要求保留目标、约束、决定、关键实体、最新纠正与未完成事项。
模型/结构校验或持久化失败时保留旧摘要及原消息，不推进处理游标。

## 迁移与回滚

迁移版本：`20260930_0016`，上一个版本：`20260909_0015`。

部署新代码前，在备份数据库后执行项目现有迁移命令：

```powershell
.venv/Scripts/python.exe -m alembic upgrade head
```

迁移只依据已知分类及可验证的用户/会话/运行归属分类，不调用模型，也不重新提取历史。
已有记录和状态保留；新增默认值为使用开启、自动整理关闭。
回滚新代码并停下后台任务后，可执行：

```powershell
.venv/Scripts/python.exe -m alembic downgrade 20260909_0015
```

回滚移除新列和任务表，保留记忆行及证据/版本元数据；会失去新增作用域和用户设置字段。
数据库迁移与代码版本需保持一致；运行新代码时不可仅回滚数据库，否则 ORM 查询会因缺少新增列而失败。
