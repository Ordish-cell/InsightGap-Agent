# 研究摘要

Based on 4 evidence items, the research question '文档里里讲了啥？' points to a traceable information-gap opportunity. Key evidence: 7.4 关键路径与里程碑
关键路径为：1.1项目启动 → 1.2需求收集 → 1.3需求分析 → 2.1范围说明 → 2.3进度基准 → 3.1环境准备 → 3.2架构权限设计 → 3.4部署方案 → 4.1基础部署 → 4.2成员与项目校园化 → 4.3任务卡片主流程 → 4.4周期/模块/视图 → 4.8安全加固 → 5.1联调 → 5.2功能测试 → 5.5缺陷修复与回归 → 6.1演示部署 → 6.3验收演示 → 6.4项目归档。
7.5 进度控制办法
每周召开一次固定周会，检查本周计划、已完成任务、阻塞问题和下周计划。周会纪要存入系统页面知识库。
任务状态统一使用“待处理、进行中、待测试、已完成、已关闭”五类，任何任务延期超过2天必须说明原因并提出恢复措施。
范围变更必须由项目经理记录原因、影响、是否调整工期和工作量，未经评审不得进入当前版本。
测试阶段建立缺陷优先级，高优先级缺陷必须在验收前关闭，中低优先级缺陷允许记录为后续优化。
关键路径任务由项目经理重点跟踪；如果关键路径任务延迟，则优先通过调整非关键任务、压缩会议时间或增加并行支持恢复进度。
